# SEO/GEO Manager product modes

## Decision

SEO/GEO Manager is not only a maintenance or publishing tool. It is the control plane used to **finish, optimize and grow** a WordPress site throughout its lifecycle.

The product remains independent from both SEO/GEO Theme and SEO/GEO Migration Bridge.

| Product | Owns |
| --- | --- |
| SEO/GEO Theme | frontend rendering, presets, semantic HTML, responsive design, accessibility, performance |
| SEO/GEO Migration Bridge | scan, clone, rescue, reset-first migration and cutover support |
| SEO/GEO Manager | site intelligence, finishing, content operations, SEO/GEO optimization, publishing, revisions, rollback and growth |

The products cooperate through explicit contracts but must remain independently installable and distributable.

## Three Manager modes

### 1. Build / Finish

Purpose: take a new, reset or recently migrated site from “technically assembled” to “ready to launch”.

Typical inputs:

- a fresh WordPress installation using SEO/GEO Theme;
- a rebuilt site after Migration Bridge;
- a staging/clone environment such as the EMMAKE `/nuevaweb/` pilot;
- an existing site that needs a controlled redesign without another full migration.

Responsibilities:

- inventory all pages, posts, menus, taxonomies, media and public URLs;
- detect missing strategic pages and incomplete content slots;
- detect links that still point to a source/production hostname after cloning;
- review titles, headings, excerpts, body content, CTAs and internal linking;
- review SEO metadata intent and active SEO authority;
- check indexability, canonical and Schema consistency;
- detect missing media/alt/context opportunities;
- create missing pages/landings as drafts;
- repair internal navigation and contextual links using current WordPress resource identity;
- verify mobile/desktop content completeness signals that can be checked structurally;
- produce a launch-readiness report;
- apply bounded changes with preview, fingerprint protection and rollback.

The Manager does not own visual layout when SEO/GEO Theme is active. It supplies or modifies semantic content models; the Theme renders them.

### 2. Optimize

Purpose: improve an already running site without requiring a rebuild.

Responsibilities:

- page-by-page SEO/GEO analysis;
- search intent and entity clarity review;
- metadata recommendations and authorized writes;
- content completeness and answer-first opportunities;
- internal-link graph improvement;
- orphan, thin, stale and duplicate/cannibalization candidate signals;
- structured-data consistency checks;
- local/GEO opportunity analysis without doorway-page generation;
- media and accessibility-content opportunities;
- content refresh proposals;
- preview/apply/verify/rollback for accepted changes.

Optimization is evidence-driven and bounded. The Manager must not fabricate proof, customers, metrics, reviews, addresses, certifications or results.

### 3. Grow

Purpose: operate the continuous organic-growth loop after launch.

Responsibilities:

- create strategic service/solution/location/campaign/hub landings;
- create and maintain normal WordPress blog posts;
- generate content clusters and validated internal-link plans;
- schedule or publish according to explicit policy;
- refresh stale content using expected-fingerprint protection;
- consume Search Console, Bing, analytics and optional keyword/competitive inputs;
- identify opportunities from real signals;
- measure published work and feed the next iteration.

Remote research/generation may help create change sets, but public rendering must remain local to WordPress.

## Lifecycle flows

### New site

```text
SEO/GEO Theme
      ↓
SEO/GEO Manager — Build / Finish
      ↓
launch-ready site
      ↓
SEO/GEO Manager — Optimize / Grow
```

### Migrated site

```text
SEO/GEO Migration Bridge
      ↓
SEO/GEO Theme
      ↓
SEO/GEO Manager — Build / Finish
      ↓
launch-ready site
      ↓
SEO/GEO Manager — Optimize / Grow
```

### Existing third-party WordPress site

```text
existing WordPress
      ↓
SEO/GEO Manager — Optimize / Grow
      ↓
accepted provider/theme adapters
```

SEO/GEO Theme is the preferred rendering partner, but Manager must remain useful on supported non-Theme WordPress installations.

## EMMAKE reference workflow

EMMAKE is the first Build / Finish reference implementation.

The Manager should be able to:

1. connect to `/nuevaweb/` and read the real current WordPress state;
2. produce a site snapshot using URLs generated by the clone itself;
3. detect any internal navigation or content links that still target the production hostname;
4. inventory Home, Services, Cases/Work, About, Careers, Insights/Blog, Contact and legal surfaces;
5. report missing/incomplete content, metadata, internal links, media and structured-data signals;
6. prepare bounded changes as a preview/diff;
7. apply accepted changes without overwriting newer human edits;
8. verify the resulting resource and URL;
9. retain a rollback reference;
10. repeat until the site reaches launch readiness;
11. then continue in Optimize/Grow mode without changing products.

## Launch readiness

Build / Finish should eventually expose a bounded readiness result with evidence grouped into:

- **Structure:** required pages/resources exist and resolve locally;
- **Content:** required strategic slots are populated with non-placeholder content;
- **Navigation:** internal links resolve to the current environment and expected targets;
- **SEO:** title/meta/canonical/indexability authority is known and non-conflicting;
- **GEO:** declared geographic intent is supported by real visible facts where applicable;
- **Schema/entities:** structured-data intent matches visible verified content;
- **Media:** required strategic media exists and has appropriate context/alt policy;
- **Editorial:** blog/archive/article surfaces work and have valid internal destinations;
- **Technical:** sitemap/discovery surfaces are present and no obvious clone-domain leakage remains;
- **Operations:** Manager can preview, apply, verify and rollback controlled changes.

Readiness is a diagnostic result, not a promise of rankings or business outcomes.

## Operator contract

The target operator loop is:

```text
request
  ↓
inspect current real state
  ↓
explain detected issue/opportunity
  ↓
prepare bounded change set
  ↓
preview diff
  ↓
apply to draft/approved target
  ↓
verify current environment
  ↓
record operation + rollback reference
  ↓
iterate
```

This is the WordPress equivalent of the fast inspect/change/verify loop used on software projects, while preserving WordPress revisions, permissions and client autonomy.

## Priority change to MVP roadmap

Because Build / Finish is now a first-class product mode, the immediate implementation priority is:

1. M1 Site Intelligence and launch-readiness snapshot;
2. M2 Preview / Apply / Rollback;
3. use EMMAKE `/nuevaweb/` as the first real finishing target;
4. M3 SEO/GEO Optimizer;
5. M4 Landing Engine;
6. M5 Blog Engine;
7. M6 measurement/growth integrations.

The Theme and Migration Bridge continue toward their own MVP closures independently; Manager development must not wait for those products to be feature-complete.
